## What the app is (my read)

An **orchestrator plus harness**. You give one **main agent** a goal; it grills
you, writes `PLAN.md`, turns the plan into **tickets** you approve, then runs
one **worker agent per ticket** in its own git branch/worktree, gates each on a
`check` command, and hands the result to you to approve or reject before merge.
Routing is separate: each agent is assigned a model and an effort rung, and it
climbs the ladder only on evidence of failure.

One Rust workspace, one core, two shells:

| Crate | Role |
|---|---|
| `crates/runner` | MIT, reusable: one turn on a CLI / Ollama / OpenAI-compatible API / A2A agent → a stream of `Event`s. |
| `crates/core` | the harness: router, providers, tools, tickets, git worktrees, skills, memory, board, MCP, companion, cloud, prefs. |
| `crates/cli` | headless shell (`scan`, `serve`, `cloud`). |
| `crates/tauri-app` | **the main app.** Tauri 2, vanilla JS in `ui/`, React/Vite chat face in `web/`. |
| `crates/app` | GPUI shell; coding workbench only, lags behind Tauri. |

Zones: **Chat** (threads on the runner; named Agents + groups), **Code** (Pair =
you + one CLI; Workbench = planner/tickets/workers, with Canvases / Wall /
Home-inbox views), **Memory** (Agent Memory Repo, a git repo of markdown),
**Apps** (sandboxed views with their own agent), plus **Settings**. Also: the
message **board**, MCP bridge, phone **companion**, and **Cloud** (a dev
server, no billing).

The coding loop is genuinely differentiated: plan-first with an approval gate,
worktree isolation per ticket, a check gate before review, diagram-first
review, start-cheap escalation, nested teams with review following the org
chart, and a shared memory repo.

## Fundamental issues, most important first

### P0 — will hurt or lose data

1. **No multi-account support and no failover.** One ambient credential per
   CLI (`harnesses.rs` reads exactly one `CODEX_HOME`/`~/.codex/auth.json`,
   one Claude profile) and one `api_key_env` per provider (`config.rs:172`).
   A 429 is retried 3× with backoff and then hard-fails (`provider.rs:128-157`)
   — no rotation, no quota accounting, no switching. All concurrent workers
   share the same credential, so one usage limit stalls the whole fleet. This
   is the biggest gap and the feature you want next.

2. **Restart is still lossy for workers.** `restore()` (`harness.rs:193`)
   marks every running/queued/awaiting agent `Failed` and every in-flight
   ticket `Failed`. Only Chat replies have true Carry-on; the planner session
   is persisted but worker CLI sessions are a local variable inside
   `finish_cli` and are gone after a restart. Approval `oneshot`s die with the
   process, so a plan waiting for your OK is auto-rejected.

3. **Companion / phone link is a live attack surface.** `companion.rs:45`
   binds `0.0.0.0`, plaintext HTTP, static long-lived bearer token, and chats
   on it drive agents that run commands. Worse, the **webhook path
   `/hook/<secret>` bypasses the token entirely** (`companion.rs:73-100`):
   anyone on the LAN who guesses the secret wakes a bot with arbitrary body.
   The chat filter only excludes app threads (`t.app.is_none()`), so **agent
   and group threads are exposed to the phone** too.

4. **Secrets at rest.** `prefs.json` holds API keys and the companion/bridge
   tokens in plaintext, and `Prefs::save()` sets mode `0600` **only under
   `#[cfg(unix)]`** (`prefs.rs:364-378`) — Windows gets default ACLs.

### P1 — reliability and scale

5. **State grows without bound, and every event ships the whole state.**
   `board` is never trimmed; `agents` (workers/scouts/triage) is never pruned
   and is fully serialized into `.backspace/state.json` on every `save()`
   (`harness.rs:645`); `parked` keeps finished `Conversation`s forever
   (`harness.rs:2356`); the `done` watch map is never cleared. Each event
   clones the entire `ProjectState` and sends it over IPC. Fine at 6 agents;
   a wall of 20 chatty agents will feel it.

6. **Panic surface.** Pervasive `lock().unwrap()`, direct indexing
   (`s.agents[id]` at `harness.rs:616, 534, 675, 2097`), `ancestry` indexing
   `agents[cur]` (`project.rs:218`) panics on a stale `parent`,
   `start_task` uses `.find(...).unwrap()` (`harness.rs:2460`), and
   `chat.rs:1102 history()` indexes `ts[id]` which panics if a thread vanished
   mid-run.

7. **No timeout and no cancel for a CLI worker turn.** `run_cli_turn`
   (`harness.rs:1330`) has no deadline; a hung CLI holds its ticket until you
   quit. Stop exists for the project now, but not a per-turn timeout.

8. **CLI workers are only half-accounted.** Their spend never reaches
   `total_cost_usd` (budgets don't apply), Codex's thread id isn't captured
   (feedback rounds start cold), and Claude workers get unrestricted `Bash`
   with `acceptEdits` — the worktree isolates the git branch, not the machine.

9. **Merge model is a serial funnel.** All workers merge into the parent's
   single worktree through one global git mutex (`harness.rs:58`); a
   conflicted merge aborts with no automatic retry beyond re-submitting. And
   `add_worktree` early-returns when `<path>/.git` exists (`git.rs:124`), so a
   re-dispatched failed ticket **reuses a stale worktree with no reset**.

### P2 — hygiene, Windows, dead code

10. **Local requests are not proxy-bypassed.** Only the board bridge uses
    `.no_proxy()` (`board.rs:161-162`). Every other `reqwest::Client` —
    `chat.rs:420`, `cloud.rs`, `fleet.rs`, `remote.rs`, `router.rs:299`,
    `harnesses.rs:575`, and the runner's A2A client — inherits `HTTP_PROXY`.
    On a machine with a proxy set (corporate network, CI, this sandbox) calls
    to Ollama on `localhost`, a local router, a local A2A agent, or a followed
    `backspace serve` peer get routed through the proxy and fail. Build these
    clients with `.no_proxy()` (or a `Proxy` that bypasses loopback). This is
    also why `runner/tests/http.rs::bad_agent_addresses_say_so` fails here:
    `127.0.0.1:1` comes back as `502 Bad Gateway` instead of a connection
    error — an environment artifact that points at a real defect.
11. `which()` accepts only `.exe`/`.cmd` on Windows (`harnesses.rs:207`);
    Windows login passes a bare name to `cmd /K` (`harnesses.rs:488`);
    `run_cli` sanitizes only `CLAUDECODE*` vars, not `CODEX_*`/`OPENAI_*`
    (`runner/src/lib.rs:345`); `Workspace::sh` uses `bash -lc` with no native
    fallback.
12. `provider.rs:137,141` sends an **empty** `x-api-key` when the key is
    missing → an opaque 401 instead of a clear config error.
13. `mcp.rs:111` reads unbounded `lines()` — one huge line is an unbounded
    allocation. `KillTree` is Windows-only; on unix grandchildren may survive.
14. **Duplicate surfaces:** two chat renderers (vanilla `chat.js` + Whirl
    React) reimplement markdown/message logic; the rail is built but
    `shell.css:12` hides it in the native shell; `#gear` is double-bound;
    `.grid.inbox`/`.ibx*` CSS and `.wbv` are dead; `design/workbench.html` is
    the **old** environment-tabs mock and is no longer the target.
15. **Toolchain mismatch:** README says Rust ≥ 1.98 for `crates/app` (gpui-pre)
    but this machine has 1.97.1, so the GPUI shell likely won't build here —
    consistent with "freeze GPUI".

## Reference: csm (how the account-switch principle works)

`csm` keeps each account in its own **profile directory** and points the agent
at it with the agent's own env var — `CLAUDE_CONFIG_DIR`, `CODEX_HOME`,
`GEMINI_CLI_HOME`, `COPILOT_HOME`. It verifies identity per profile, tracks a
provider-neutral **health record** (last used/success/failure + classification,
24h failure count, cooldown, reported usage), and on a *confirmed usage limit*
checkpoints the session, switches to the best account, and **resumes the same
conversation**. Policies: `automatic` / `manual` / `disabled`. When every
account is exhausted it can **hand off to another agent** with a structured,
redacted task brief. It never estimates usage and never switches on a plain
rate limit — only on the agent's own limit report. csm is macOS/Linux only and
Go; we would port the *principle*, not the code.
