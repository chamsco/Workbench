# UI audit, 10 Nov 2026 (round 21)

Three things were audited against the UI skills: the reviewed wireframe, the Tauri UI that ships today, and the GPUI shell in `crates/app`.

## Sources and limits

- `design-taste-frontend` (tasteskill v2). Its own section 13 says it is not for dense product UI, so only the system rules were used: shape lock, colour lock, one accent, no neon by default, contrast, states, motion, dash and dot rules. The landing-page rules (hero, eyebrows, logo walls) were not applied.
- `unslop` by Damir Sokolovsky (CC BY 4.0). Only the intro and pass order could be read (spacing, colour, icons, copy, type, layout, details, visuals, motion). The per-pass rules are not on the repo page.
- `ibelick/ui-skills` baseline-ui. The repo blocks fetching the skill file. The rules used are the ones `docs/UNSLOP-2026-11-05.md` already records: 4px scale, icon labels, tabular figures, motion discipline.
- Not run: the GPUI shell (this container has no display or GPU; `cargo check -p backspace` passes in 1m33s) and a fresh visual capture of the Tauri UI. The Tauri numbers are a static scan of `crates/tauri-app/ui`.

## Verdict

1. The wireframe passes the locks and fails on six smaller points (table A). None changes the layout.
2. The Tauri UI fails most rules at scale. It does not need fixing: it needs replacing by the GPUI build (table B).
3. The GPUI shell is the old glass design. Its plumbing carries over; its look does not.

## A. Wireframe against the skills

| Rule | Result | Evidence | Fix |
|---|---|---|---|
| One radius scale (taste 4.4) | Pass | 6 / 4 / 3 plus circles. Outliers: `.face` 36%, bars 2px | Faces become circles in GPUI |
| One accent, locked (taste 4.2) | Pass | `#ff4d2d` dark, `#c9330f` light; people keep their colours on purpose | none |
| Text contrast AA | Pass, one finding | All text pairs 4.5:1 or more in both themes. Light accent on the frame is 4.13:1 | Rule: accent text only on card or raised; on the frame the accent is a glyph. Now a test (`accent_on_the_frame_is_for_glyphs_only`) |
| No neon glow by default (taste 9.A, unslop) | Deliberate exception | `--glow` is used twice: the New thread button and the frame corner | Charles asked for the button glow. Keep one glow per screen, behind one token |
| No ornament (unslop) | Deliberate exception | Dot texture and corner glow on the frame | Charles asked for a livelier frame. Pre-bake as one image so it can be switched off |
| Em-dash ban (taste 9.G) | Pass | 0 em-dashes, 2 en-dashes | Replace the 2 |
| Middle dot rationed (taste 9.F) | Fail | 72 dots; many lines carry two or three | Copy pass: one per line, or split into columns |
| No hand-rolled icons (taste 3.C) | Fail | 22 custom SVG symbols | GPUI uses one family (gpui-kit icons); redraw nothing |
| Tabular figures (baseline-ui) | Fail | 0 uses; usage %, cost, counts are proportional | Enable tabular figures on every number in GPUI |
| Type scale | Fail | 13 sizes, including 8.5, 10.5, 11.5, 12.5, 13.5 | Collapse to 11 / 12 / 13 / 14 plus two heading sizes |
| States (taste 4.5) | Fail | One happy state per screen. No empty, loading, error, offline or hibernated | State matrix in `UI-PLAN.md` |
| Motion | Pass | Every transition 200ms or less; one reduced-motion block | Honour reduced motion in GPUI |
| Fake-precise numbers (taste 4.9) | Mock | 62% left, 78% left, $0.42 are invented | Real data needed, see below |
| Icon-only buttons labelled | Pass | Every function button has an aria-label | GPUI accessibility is a risk, see C |

The usage meter needs a decision. `crates/core/src/usage.rs` reads token counts from Claude Code and Codex session logs and says "not logged" for anything the log lacks. A "% left in the 5h window" is a quota figure. Whether either log carries it has not been checked. If not, the left meter shows tokens and cost, not "% left".

## B. The app today

### Tauri UI (`crates/tauri-app/ui`: about 7.1k lines JS, 4.0k CSS, 177 Rust commands)

| Rule | Result | Evidence |
|---|---|---|
| One radius scale | Fail | 19 distinct values from 1px to 20px, plus 39 pills at 999px |
| Restrained shadows | Fail | 143 `box-shadow` declarations |
| Motion discipline | Fail | 57 transitions or animations longer than 200ms |
| Em-dash ban | Fail | 33 in 6 JS files (`app.js` 11, `home.js` 6, `quiet.js` 6, `shell.js` 7, `dash.js` 2, `frame.js` 1) |
| Tabular figures | Fail | In 3 stylesheets only |
| Icon labels | Partial | 191 `aria-label` against 378 `<button`; the share that are icon-only was not counted |
| Reduced motion | Partial | Present in 4 stylesheets and 2 scripts |
| Typeface | Differs | Inter and JetBrains Mono. The wireframe uses the system font |

### GPUI shell (`crates/app`: 6.2k lines, coding workbench only)

| Rule | Result | Evidence |
|---|---|---|
| Palette | Fail | The old glass design: translucent panes, three blurred colour blobs, violet page accent. Six hues in the palette against one accent plus status colours |
| One radius scale | Fail | 13 values from 1.1px to 14px, plus full |
| 4px scale | Fail | 295 of 471 `px()` values are not multiples of 4 |
| Window | Differs | Glass and traffic-light placement are macOS only (`GLASS = cfg!(macos)`); no Windows chrome |
| Fonts | Pass | `.SystemUIFont` on macOS, Segoe UI on Windows, Inter elsewhere; matches the wireframe stack |
| Motion | Pass | No animation code |
| Screens | Gap | One view. No thread inbox, projects, agents, memory, apps, settings sidebar, patches drawer |

## C. What GPUI can and cannot do for this design

Checked in the pinned `gpui-pre 0.3.6` source.

| Wireframe feature | GPUI | Plan |
|---|---|---|
| Notch and curved tab feet | `PathBuilder` | Draw as paths |
| Windows caption buttons | `WindowControlArea::{Drag, Min, Max, Close}` | Hit areas plus drawn glyphs |
| Mica | `WindowBackgroundAppearance::MicaBackdrop` (Windows 11) | Off by default; the frame is opaque |
| Radial corner glow | Only `linear_gradient` and `pattern_slash` | Bake into one image, as `desk_image` already does |
| Dot texture | Not native | Same baked image |
| Inset highlight | `BoxShadow` has no inset | 1px overlay element |
| Screen reader support | `accesskit` is a dependency | Unverified. Treat as a risk until a test proves it |
| IME and text input on both OSes | Not checked | UI4 exit test |

## Order of fixes

1. Tokens and layout as code, tested against the wireframe. Done: `crates/chrome` (UI0).
2. Replace the GPUI palette and radii with the tokens before any new screen is drawn.
3. Copy pass on the wireframe (dots, en-dashes, type scale) so the port copies clean text.
4. State matrix before the screens it covers.
5. Retire the Tauri UI screen by screen, not all at once.
