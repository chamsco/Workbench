# core-harness

Opened every cited line in `crates/core/src/harness.rs` and `crates/core/src/fleet.rs` and read 15 lines around each: 22 findings, 22 rulings — 16 Delete, 5 Refactor, 1 Keep, 0 Rejected. No line number and no quote was wrong; every citation matched the file text verbatim, so nothing was dropped for a bad citation. One finding was confirmed by git history rather than by eye: `harness.rs:2792` is a truncated compiler note — `ea7152a` (the repo's first commit) carried the whole sentence, "Explicit BoxFuture return type breaks the drive → spawn → run_sub → drive async type cycle", and the rename to `run_worker` mangled it, leaving the fragment glued in front of `run_worker`'s doc. Two audit findings contradicted each other: the row at `harness.rs:2412` says the step-3 comment at 2455 "carries a why", while the separate row at 2455 calls it a prose translation; reading 2455–2458 settles it for Delete (the boolean and the human path below say the same thing), and the surviving step comment at 2433 then needs its orphaned `2.` trimmed. The banner rows are single findings covering five lines each, and the 2412 row covers 2484 as well; those extra lines are named in the "why" cell rather than given rows, so the ruling stays 1:1 with the audit. Two borderline delete calls were resolved in favour of Delete after checking the code: `harness.rs:410` claims "spend and the board come back", which `restore`'s own doc omits but the code makes plain (the function returns `old` wholesale, so every unmentioned field survives), and `harness.rs:198` explains a `filter(|_| !jobs.is_empty())` guard whose effect is the early return three lines below. The one Keep rests on a platform fact, not taste: a restart is the OS killing the process, so no in-repo code can make the dead turn report success while its branch, worktree and saved CLI session survive on disk — that asymmetry is why the status must read `Interrupted` and re-dispatch resumes the same session; only the `(the audit's P0-2)` provenance in the same comment is noise, worth a separate trim. `harness.rs:1215` also needed a factual correction: its first clause ("always WSL") and "which a tool call cannot ask for" are contradicted by line 1218, which does pass `hyperv` through, so only the elevated-host half is a real platform limit.
