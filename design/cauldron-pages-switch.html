Streams, Agents, Memory: one switch, folders for tidying

A three-way switch at the top of the sidebar replaces the main area with Streams, Agents or Memory. Agents and Memory open as labelled mockups for now. Streams belong to folders. The open design question was how folders show in the sidebar, so that comes first.

My picks. Sidebar B: folders on top, state as a dot, with a pinned "Needs you" group. The sidebar list never changes with the switch. Agents and Memory carry their own list inside the page. Details and what it costs below.

1. Folders in the sidebar

Same eight streams in three folders plus one unfiled, arranged two ways. B is shown again with search, and folded.

PickB. Folders are the stable grouping, state is a dot on the row.
Why not AA groups by the thing that changes every few minutes. A stream moves between sections as it starts and finishes, and one folder shows up under all three states, so finding "everything in workbench" means scanning the whole list. Tidying and search were the point of folders, and A fights both.
What B costsYou no longer see every running stream in one section. Mitigations: "Needs you" stays pinned on top (and its streams are not repeated below), a running stream rings its row, and a collapsed folder shows a purple dot when something inside needs you. With every folder collapsed you see counts only.
Open or closedA folder is open when it holds a running or waiting stream, closed otherwise. A manual toggle is remembered.
SearchOne field over stream titles and folder names. A hit shows its folder as a chip, so results from different folders sit in one list.

2. The switch and the three destinations

Switching only replaces the main area. Clicking any stream in the sidebar brings you back to Streams. The folded rail stacks the switch vertically, with usage on top.

Real in the buildThe switch, the sidebar grouping, folder membership on a stream, the folder chip in the new-stream box, folder search.
PlaceholderThe Agents and Memory pages. They carry a "Mockup" tag and example content, nothing presented as the user's data. Each button opens its mockup, so the route is there when the real page replaces it.
Why self-containedIf the sidebar list became agents or notes when you switched, you would lose one-click access to a stream while reading Memory, and the sidebar would mean three things. Master and detail both live inside the page instead.

3. Decisions I made

  • A stream's folder is the project path core already stores on every thread, so grouping needs no new field. The name and machine come from the project record. Streams with no project sit in "Unfiled".
  • Risk: if that path is also where the stream runs, "Move to folder" would change where it runs. The build should confirm that before wiring Move, and keep the working directory separate if it does not.
  • The new-stream box suggests the folder whose directory matches where you are. It is shown in the chip and never filed silently.
  • Deleting a folder moves its streams to Unfiled. It never deletes streams.
  • Move a stream by dragging it onto a folder, or "Move to folder" in its row menu.
  • The same switch and sidebar on Windows; nothing platform specific.
